# 当前代码情况与发布范围

整理日期：2026-10-23。本文针对博客仓库 `xiaolai06/my_blog`，不是四个业务项目各自的上线报告。

## 1. 项目定位与技术组成

这是一个已经可以静态构建的个人作品集与博客。主要结构在构建时由 Astro 生成，搜索、筛选、主题、图片查看、音乐与场景切换由浏览器脚本完成。

| 部分 | 当前技术 | 作用 |
| --- | --- | --- |
| 页面与路由 | Astro 7.4.0 | 页面生成、布局、静态路由与站内页面过渡 |
| 文章 | Markdown / MDX、Astro Content Collections | 字段校验、目录、代码、组件与交互示例 |
| 交互 | TypeScript、Motion 14 | 页面生命周期、筛选与切换、图片查看和动效 |
| 样式 | 原生 CSS、局部组件样式 | 主题、排版、项目案例和桌面适配 |
| 图片 | WebP、SVG、Sharp | 插画、真实截图与媒体处理 |
| SEO 输出 | RSS、Astro Sitemap、页面元信息 | canonical、订阅与站点地图 |
| 构建环境 | Node.js 24、npm 锁文件 | 本地和 GitHub Actions 使用同一依赖定义 |
| 托管方式 | 静态网站目录 | 由服务器的 Caddy / Nginx 或静态托管平台提供文件 |

网站本身没有常驻 Node 业务服务，也没有后台管理、评论数据库或线上登录 API。业务项目的运行截图和说明是作品内容；访问项目详情不会启动 TaskHub / ClothHub 的后端。

## 2. 已有页面和内容

| 模块 | 现有内容 |
| --- | --- |
| 首页 `/` | 场景背景、精选项目、手记入口、个人侧栏和日历 |
| 项目 `/projects/` | 项目集合与分类；ORULINK、TaskHub、ClothHub、学绩四个详情 |
| 手记 `/blog/` | 8 篇公开文章；分类、关键词、标签、时间筛选与阅读页 |
| 关于 `/about/` | 个人资料、教育经历、技能、获奖与经历 |
| 音乐 `/music/` | 在线与本地音频、播放状态、时钟与专注功能 |
| 教学示例 `/examples/retrospectives/*.html` | 9 个隔离的交互练习，随文章按需加载 |
| 其他 | 404、RSS、站点地图和 FastAPI 教学项目下载 |

当前构建生成 **27 个 HTML 文件**：18 个正式页面与 9 个交互示例；RSS 和站点地图另外生成。数量会随公开文章与项目增加而变化。

原始 Astro 样例和未公开的旧文保留在源码中，由 `draft` 控制；只有公开内容生成正式文章地址。示例练习标明教学用途，不接受或处理真实登录信息，不签发证书，也不会发送邮件。

## 3. 代码如何组织

```text
src/
  pages/                 页面入口、动态路由和静态示例端点
  layouts/               全站布局与文章布局
  components/            导航、风景、项目、文章与播放器组件
  data/                  个人资料、项目文案与示例索引
  content/blog/          Markdown / MDX 文章
  examples/              可展示的教学示例源码
  scripts/               浏览器交互、生命周期、音乐与动效
  styles/                排版、主题、布局与模块样式
public/                  网站直接使用的公开媒体、字体、下载包
artwork/                 设计原图；保留在仓库，不进入 dist
scripts/                 素材维护、正式构建和发布检查工具
docs/                    内容维护、设计资料与发布文档
.github/workflows/       推送后的自动构建与检查
```

浏览器端通过页面生命周期统一初始化并清理交互，适应 Astro 的站内换页。主题和部分偏好保存在访问者的浏览器，本地歌曲依赖浏览器存储；这些不是服务器上的用户账号数据。

## 4. 这次发布准备做了什么

1. 整理仓库首页文档、实际代码结构、内容维护入口和服务器发布步骤。
2. 补全环境变量示例与 Node 版本约定，明确网站部署在域名根目录。
3. 增加 `build:release`：正式地址缺失或仍是示例 / 本地地址时直接停止，避免发布错误的 SEO 地址。
4. 增加 `check:site`：检查生成文件、HTML / CSS 引用的站内页面与资源，以及 canonical / RSS / sitemap 的地址一致性。
5. 增加发布地址测试与教学 ZIP 内容核对，自动构建时检查。
6. 增加 GitHub Actions：推送 `main` 或提交合并请求后验证；配置正式域名后提供服务器可用的静态文件包。
7. 扩充忽略规则，排除本地运行目录、调试截图、环境文件、数据库、私钥和依赖缓存。

这些是发布前的构建与资源检查，不等于第三方音源可用性检查、完整安全审计或所有浏览器的功能回归。

## 5. 素材体积与后续维护

本次整理时 `public/` 大约 **128 MB**，原始设计素材 `artwork/` 大约 **89 MB**。仓库保留了一些旧场景版本；正式页面根据当前配置按需加载资源，浏览器不会在首次进入时下载整个 `public/`。

所有 `public/` 文件都会进入 `dist/`，所以服务器发布包仍包含旧素材。后续可在核对全部动态资源引用后独立清理旧版本，或把视频放入对象存储；本次保留现有素材，避免因误删影响场景回退和文档示例。

## 6. 上线前还要提供的信息

GitHub 推送仅更新源码。仓库中的自动构建不会自动覆盖服务器文件；服务器上线按 [发布说明](deployment.md) 单独执行。
