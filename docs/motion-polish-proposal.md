# 博客与音乐空间动效优化方案

日期：2026-10-21

本文是基于当前源码及音乐空间界面检查整理的改进建议，不代表以下效果已经实现，也不代表已完成帧率测试。

页面转场、首页卡片的完整交互过程、筛选排序及详情切换的细化设计见 [博客页面与内容动效设计说明](motion-design-spec.md)。

## 1. 整体方向

保留当前电脑端居中、内容宽度、首屏比例、双列项目、侧栏、完整景观底部和手机断点。正文页面采用轻柔、明确的反馈，音乐空间承载更丰富的光影与声音联动。

动效需要表达三个信息：操作已收到、状态正在变化、结果已经稳定。装饰效果集中在风景区域；阅读、搜索、拖动和键盘操作始终优先响应。

以下时长和数量是建议起点，最终以实际窗口、设备和连续操作的观察结果调整。

## 2. 当前已经具备的基础

| 模块 | 当前实现 | 下一步重点 |
| --- | --- | --- |
| 页面切换 | Astro 客户端路由、整页短淡入淡出、独立导航指示线 | 统一节奏，检查连续跳转与返回状态；避免重复入场 |
| 项目筛选 | 已有 FLIP 位移与新卡片淡入 | 优化选中胶囊和快速切换，保留现有卡片排布 |
| 卡片 | 已有轻抬升、封面小幅跟随、局部微光 | 降低多种效果同时发生的强度 |
| 搜索及手机导航 | 已有可反向中断的展开收起 | 区分鼠标与快捷键操作，保证焦点及时可用 |
| 场景切换 | 图片先解码、再叠化；最多两层；连续选择取最后目标 | 补齐准备中、成功和失败反馈 |
| 花瓣 | 博客已有分层轨迹、离屏暂停和减少动态支持 | 统一风向与密度，不重复叠加粒子系统 |
| 音乐 | 持久化播放器、曲库、电台、收藏、同步歌词、拖动、专注计时 | 优化各状态之间的衔接 |
| 音乐氛围 | 视频壁纸、花瓣、光点、呼吸光、播放状态跳动条 | 让视觉状态与实际出声、缓冲和暂停一致 |

音乐时钟旁的跳动条目前是 CSS 循环动画，并非真实频谱；播放与暂停决定它是否运动。博客的图片场景与音乐空间的视频壁纸也是两套已有机制，适合分别优化。

## 3. 第一批：优先改善流畅性和选择反馈

### 3.1 页面切换与返回

- 保持导航和悬浮控制的位置稳定，正文短暂叠化。
- 可先试入场 220–280 ms、退场 140–180 ms；两者重叠执行，不先等整页消失再出现下一页。
- 路由已经在做过渡时，正文不重复播放整套入场动画。
- 快速点击以最后目的地为准，不积压过渡。
- 从详情返回时恢复列表筛选、关键词和滚动位置。这比额外增加一次大幅滑动更有实际价值。
- 项目封面到详情的共享元素过渡作为后续试验：只在素材、裁切和比例适合时启用；普通导航继续用短叠化。

### 3.2 分类、标签、曲库选项的选中状态

- 在原有按钮内部增加一个滑动的选中背景，约 180–220 ms；文字与边框同步换色。
- 按下反馈控制在 80–120 ms、缩放约 0.98；不改变按钮占位尺寸。
- 项目筛选继续使用已有 FLIP，建议将常规位移收敛到 220–280 ms；新出现卡片只做很短的错峰，整体不形成等待队列。
- 连续点击时从当前画面接续；焦点及选中属性立即更新，动画只负责视觉过渡。
- 收藏可做一次约 180 ms 的小幅心形回弹；同时保留明确的已收藏状态。
- 曲库收藏更新应尽量只更新受影响的行。当前 `renderList()` 重建列表，可进一步保留滚动位置和键盘焦点。

### 3.3 搜索、日历与樱花菜单

- 鼠标打开搜索采用约 180–220 ms 的轻位移与淡入；关闭约 120–160 ms。
- Ctrl / Command + K 立即让输入框可用，采用更轻、更短的视觉反馈。
- 日历跨月仅让日期区域按方向轻移约 6–8 px，标题与结果短叠化；外框和侧栏占位不变。
- 樱花菜单保留现有扇形结构，统一展开与收起节奏；键盘选择减少延迟。
- 场景图尚未解码时，选项给出轻量“准备中”提示，画面继续显示旧场景；成功后确认选中，失败时提供重试。

## 4. 音乐空间：最值得打磨的六项

### 4.1 播放器和计时卡片展开收起

现状：通过 `data-widget-minimized` 配合 `display:none` 隐藏，主体没有与博客搜索相同的完整进出场流程。

建议：

- 从面板所在边缘轻移 8–12 px，配合透明度和约 0.985 的轻微缩放；展开 200–240 ms，收起 140–180 ms。
- 动效放在面板内层视觉容器上；外层继续保存现有拖动坐标，避免与居中变换、拖动位置冲突。
- 收起过程中立即禁止隐藏内容被点击或聚焦，结束后再隐藏；快速重新展开能从当前帧继续。
- 快捷开关始终留在原位置；音乐、计时和音频节点不因面板收起而重置。

### 4.2 歌词跟随与手动查看

现状：已有逐行时间戳、高亮、自动居中和点击跳转；大字窗口当前行会调整字号。尚未看到独立的手动滚动暂停跟随机制。

建议：

- 固定行高与字体尺寸，主要通过颜色、透明度和很小的视觉缩放区分当前行，降低文字跳动。
- 行切换约 180–240 ms，滚动距离较大时直接定位或短叠化，避免长距离追赶。
- 用户滚轮或触摸查看其他歌词时暂停自动跟随约 4 秒，提供“回到正在播放”入口。
- 拖动播放进度后立即定位歌词；只有可见歌词窗口参与高频更新。
- 现有普通 LRC 提供的是逐行时间，不据此伪造逐字卡拉 OK；逐字效果需要相应的时间数据。

### 4.3 播放、暂停、缓冲和切歌的反馈

现状：已有 `waiting` / `playing` 加载标记和错误文案；氛围状态主要依据音频是否暂停。

建议：

- 以实际播放、等待、暂停、错误区分视觉状态，避免加载时跳动条仍像在正常出声。
- 缓冲持续约 250–300 ms 再显示加载反馈，减少短等待时的闪烁；保留重试和换歌入口。
- 播放按钮图标与歌曲信息短叠化，连续切歌立即响应，较早请求不能覆盖最后选择。
- 进度条可在播放器可见且正在播放时平滑跟随；拖动时直接跟手，隐藏、暂停或页面不可见时停止视觉逐帧更新。
- 先做视觉衔接。真正的声音交叉淡化涉及多个音源及直播兼容，作为独立功能评估，不与普通切歌动效混在一起。

### 4.4 面板拖动手感

现状：已经支持边界限制、位置保存、键盘微调和 Home 归位；指针移动时直接写入 `left/top` 并读取面板尺寸。

建议：

- 拖动开始时缓存尺寸与边界，每帧最多提交一次位移，优先用视觉变换移动，结束后落到最终坐标。
- 指针移动时面板紧跟，不增加惯性拖尾；释放后可选 120–180 ms 的短距离边缘贴靠。
- 拖动只触发轻微阴影变化，不持续动画大面积模糊。
- 继续保留 5 px 左右的点击/拖动分界、触摸取消、窗口缩小后的边界修正和键盘替代操作。

### 4.5 真实频谱与音乐微光：第二批可选增强

预期效果：在时钟旁或播放器现有区域呈现低矮的 16–24 条频谱；背景只做低幅度、经过平滑的明暗变化，不逐拍闪屏。暂停时频谱柔和回落，缓冲时显示清晰的等待状态。

这项需要先验证音源兼容性：

- 本地音频、同源资源和明确允许跨域分析的音源优先验证。
- 部分在线电台能播放却不允许 Web Audio 分析；不能将所有资源直接接入 `MediaElementAudioSourceNode`。
- 现有音频元素跨页持久化。分析节点一旦接管媒体路径，不能只“关闭频谱绘制”就假定恢复普通跨域播放；必须先验证本地音乐与未知电台来回切换时的音频通路和回退。
- 无法安全分析的资源继续正常播放，使用明确的装饰氛围，避免把模拟跳动称为真实频谱。
- 起步只做频率/响度的平滑响应，不承诺 BPM、节拍识别或情绪识别。
- 不申请麦克风权限；不上传本地歌曲做分析。

因此真实频谱放在兼容性原型通过之后，优先级低于面板、歌词与播放反馈。

### 4.6 专注状态与完成反馈

- 开始时进度环与状态短暂确认，计时中保持安静。
- 暂停后保留进度，数值使用已有等宽数字，不让卡片宽度随时间变化。
- 完成时可选一次约 1 秒、5–8 片的小范围樱瓣或一次柔光；只在音乐空间可见时播放。
- 后台结束计时后，返回时显示完成状态，不补放一串庆祝动画，也不自动打断音乐。

## 5. 背景和趣味效果

| 效果 | 合适的位置 | 建议强度和条件 |
| --- | --- | --- |
| 分层风与落花 | 首页、景观底部、音乐壁纸 | 延用已有轨迹系统，统一风向、速度和远近，不另建重复粒子层 |
| 鼠标经过带起轻风 | 电脑端景观区 | 可选；低频、短暂、局部响应，远离正文与交互控件 |
| 月夜萤火与水面微光 | 对应夜景、水景 | 调整已有光点，低亮度、低速度；不让没有水的画面也出现水波 |
| 音乐呼吸光 | 音乐空间 | 优先打磨现有呼吸光；真实音频分析可用后，再加入轻微响度响应 |
| 专注完成樱瓣 | 音乐空间计时卡片附近 | 一次性、小范围、可关闭 |

音乐页源码当前生成 76 个花瓣节点和 22 个氛围光点。增加效果前先测现有负载并按档位限制活动数量。可先试电脑均衡档约 24–36 片、手机约 8–16 片；这些数量是调试起点，不是性能保证。

目前景观图片与视频中已经包含完整画面。树冠、云层和人物没有独立图层时，大幅形变或全景鼠标视差可能影响构图，需要素材支持和单独验收。

## 6. 动效强度与默认值

在已有场景/体验设置中提供选项，避免增加新的常驻工具栏：

| 档位 | 使用方式 |
| --- | --- |
| 静谧 | 轻微状态换色与短叠化，背景静止；适合专注阅读 |
| 均衡，默认 | 完整操作反馈、少量落花、原有场景过渡 |
| 沉浸，可选 | 音乐空间增加可用的频谱、微光和趣味反馈 |

手机默认采用更少粒子并关闭鼠标跟随。系统减少动态效果优先于档位；保留功能和清晰状态，取消位移、粒子和大幅缩放。已有暂停动效入口继续有效，并覆盖正在执行的新增动效。

## 7. 实施顺序

1. 第一批：统一动效节奏；筛选/曲库选中反馈；音乐面板进出场；歌词手动查看；播放与缓冲状态；拖动优化。主要收益是连续操作更顺手。
2. 第二批：场景准备反馈、时段氛围精修、可选专注完成效果、档位设置；同时做频谱音源兼容性原型。
3. 第三批：原型通过后接入真实频谱和微光联动；按画面条件试验项目封面共享过渡、景观轻风互动。

正文页面长期保留轻动效；表现力最强的功能集中在音乐空间，并允许用户主动选择。

## 9. 验收方式

- 原布局：1366、1440、1920 桌面宽度，以及 390/375 手机宽度；动效开关前后静态容器宽度、居中位置、网格列数一致，景观底部完整。
- 连续操作：快速筛选、连续换页、前进后退、反复展开收起、拖动中取消，最终状态正确，无动画队列积压。
- 音乐连续性：换页面及收起卡片不重置音频；切换曲库不停止音乐；缓冲与播放图标对应实际媒体状态。
- 歌词：自动跟随、手动查看、回到当前行、进度跳转、无歌词和纯音乐状态都清楚。
- 兼容性：本地文件、可分析远程音源、不可分析电台、网络失败均单独验证，频谱失败不能影响出声。
- 性能：测拖动、滚动和音乐空间同时运行时的帧耗时；以桌面接近 60 fps 为目标，约 16.7 ms 的帧预算用于诊断，不以肉眼顺滑替代性能记录。
- 资源：隐藏页面或离开音乐模式时停下无用绘制与装饰更新；音频、专注计时的实际状态照常保留。
- 可访问性：键盘、触摸、减少动态、焦点返回、面板边界和文字对比度一起检查。

## 10. 参考依据

- [Astro 视图过渡与状态持久化](https://docs.astro.build/en/guides/view-transitions/)：继续保留现有跨页播放器状态机制；持久化并不代表所有 CSS 动画都会自动保持连续。
- [web.dev 高性能动画指南](https://web.dev/articles/animations-guide)：优先动画变换和透明度，对布局、绘制及图层开销进行实测。
- [Web Audio 规范：跨域媒体的安全限制](https://webaudio.github.io/web-audio-api/#security-with-mediaelementaudiosourcenode-and-cross-origin-resources)：允许媒体播放不等于允许读取声音数据；不合适的分析路径可能输出静音。
