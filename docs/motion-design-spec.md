## 1. 整体效果

保留现有电脑端居中容器、首屏高度、双列项目、右侧栏、卡片尺寸、完整景观底部和手机断点。视觉方向是：背景舒缓，内容轻盈，操作及时，选择有连续性。

日常操作使用短促、克制的反馈；更明显的表现集中在首次进入、列表进入详情、主动切换场景和进入音乐空间。这样的分配参考了 Carbon 对日常操作与表达性动效的区分，而不是让每次点击都成为一次演出。[参考：Carbon Motion](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)

当前已经有整页淡入淡出、卡片轻抬升与封面微动、筛选位移、滚动入场和花瓣。下一步重点是协调这些效果、区分触发场景，并补齐状态之间的衔接。

## 2. 建议采用的效果总表

| 场景 | 用户看到的表现 | 建议节奏 | 优先级 |
| --- | --- | --- | --- |
| 首次打开首页 | 景观先可见，标题、说明、按钮小幅错峰进入 | 单组 280–320ms；组间 35–45ms | 第一批 |
| 卡片滚入视野 | 按阅读顺序轻抬进入，落定后保持静止 | 260–300ms；相邻 30–40ms | 第一批 |
| 鼠标悬停卡片 | 卡片轻抬，封面小幅放大，箭头沿指向移动 | 160–220ms | 第一批 |
| 选择项目分类 | 选中背景滑向目标，保留项目移到新位置，新项目淡入 | 220–280ms | 第一批 |
| 顶部导航换页 | 导航指示线移动，主体短叠化，头部和工具保持稳定 | 220–280ms | 第一批 |
| 列表进入详情 | 项目名称衔接到详情标题；同图时才展开图片 | 280–360ms | 第二批 |
| 详情功能标签切换 | 选中态连续移动，文字和截图局部切换 | 180–240ms | 第一批 |
| 手记排序 | 同一篇文章平滑移动到新位置 | 220–280ms | 第一批 |
| 手记翻页 | 结果区短淡入，轻微方向提示 | 180–240ms | 第一批 |
| 搜索结果变化 | 输入即时更新，结果轻淡入，不逐项排队 | 100–160ms，可取消 | 第一批 |
| 截图放大 | 从所点截图展开，遮罩淡入；关闭回到原图 | 240–300ms | 第二批 |
| 场景与音乐切换 | 资源准备好再叠化，控制区立即反馈 | 背景 450–700ms | 第二批 |

时长表示视觉过程，不是操作开始前的等待时间。按钮、链接和输入应当立即响应；连续操作取用户最后选择。

## 3. 首页从打开到滚动的完整过程

### 3.1 首屏分镜

1. 景观、导航和文字的布局立即成立，图片加载时保持原有占位与背景底色。
2. 标题以约 8px 的轻微上移与透明度变化进入；中文整行出现，保持原来的换行。
3. 英文、说明、按钮分别延后约 35–45ms，整体在约 400ms 内安定。
4. 首屏已经可见的项目直接可读；页面转场期间不再叠加一轮卡片入场。
5. 向下滚动时，尚未出现的项目和手记才进行一次轻入场。

不增加开屏等待。网络慢、图片解码失败或动画脚本失效时，文字和链接仍完整可见。

### 3.2 卡片出现样式的选择

| 方案 | 外观与感受 | 适用位置 | 建议 |
| --- | --- | --- | --- |
| 轻抬淡入 | 卡片从下方约 10px 落到既定位置，纸面逐渐清晰 | 首页项目、手记、侧栏 | 默认采用，最贴合当前纸面与樱花风格 |
| 封面揭示 | 卡片与文字先可见，封面遮罩从下向上揭开 | 少量重点项目的首次出现 | 可选；同一屏只给少量卡片使用 |
| 立体翻转 | 卡片翻面或明显倾斜后展开 | 独立实验页面或主动触发的彩蛋 | 不作为首页默认，正文信息容易被运动遮挡 |

默认采用第一种。同一行两张卡片按从左到右的顺序错开约 35ms；只计算当前进入视野的这一小组，不按全站索引累积等待。手机单列按自上而下的阅读顺序。

错峰适合表达列表和网格的出现次序，可参考 [Motion 的 stagger 示例](https://motion.dev/docs/stagger)。这里使用短错峰和有限分组，具体数值由本博客的卡片密度决定。

### 3.3 一张卡片在不同状态下怎样动

| 状态 | 具体表现 | 协调规则 |
| --- | --- | --- |
| 首次滚入 | 透明度约 0.5 → 1，向上约 10px | 只播放一次；滚回视野不重播 |
| 悬停 | 整卡上移约 3px；封面在当前基础上增加约 1–2% 缩放；箭头移动约 2px | 缩放只在图片裁切区内发生，卡片宽高不变 |
| 光标经过 | 可保留当前低强度局部微光，范围集中在封面 | 微光与封面跟随两者以一种为主，避免多层同时追随 |
| 按下 | 轻微压下约 1px，快速反馈 | 立即允许跳转，不等待按压动画结束 |
| 筛选后仍存在 | 从原位置移动到新位置 | 不再淡出和重新入场，保留用户识别 |
| 筛选后新增 | 在最终位置轻淡入 | 最多约 80ms 的总错峰，不排长队 |
| 筛选后移除 | 短淡出后让位 | 离场视觉层不可点击、不占键盘焦点 |
| 返回列表 | 恢复筛选、分页和滚动位置 | 不把整个列表重新当成首次打开 |

卡片入场、筛选位移与悬停需要协调，不能同时争用同一层的位移。入场过程中悬停或获得键盘焦点时，应结束入场并立即提供操作反馈。

侧栏跟随所在内容区一次轻淡入即可；日历数字、标签和每一行说明不各自延迟播放。底部景观保持原来尺寸和完整可见，只保留原有低强度环境运动。

## 4. 页面转场按照内容关系设计

### 4.1 首页、项目、手记、关于之间

采用短叠化，导航的选中指示线连续移动。头部、固定工具和持久化音乐播放器保持稳定。正文可在内部增加约 6px 的轻位移，但不要整体平移真实的 html、body 或页面外框。

页面切换与首屏入场只保留一次主要表达：普通导航让转场负责衔接，首次直接打开才播放首屏分组入场。

### 4.2 项目或手记列表进入详情

优先让同一个名称从卡片标题衔接到详情标题，正文随后短淡入。这能表达“打开了这一项”，同时保留现有详情排版。

如果前后确实使用同一张封面，再采用图片从卡片位置展开到详情位置的效果。当前项目列表是插画封面，项目详情主要是产品截图，因此项目默认采用名称衔接，不能强行把两张不同图片拉伸变形，也不为转场新增详情大封面。

原理与效果可看 [Chrome View Transitions 说明](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)及文中链接的[图片展开演示](https://simple-vt-demos.jakearchibald.com/6-expanding-image/)。同名元素的前后快照可衔接位置与大小；不支持时保留正常导航或短淡入。

### 4.3 返回与连续跳转

返回列表优先恢复位置和筛选状态，在来源仍存在且可见时反向衔接；来源已不可见或不存在时退回短淡入。不要为了寻找来源卡片自动把用户拉到别的位置。

快速点击导航、切换后立即返回、鼠标移入又移出时，动画应接续当前状态或取消旧目标，不能播放完一条队列才响应。连续性可参考 [Emil Kowalski 关于 CSS transitions 的说明](https://animations.dev/learn/css-animations/transitions)。

## 5. 内容切换的差异化处理

### 5.1 项目分类

“全部 → 校园生活 → 经营管理”的选中底色沿着同一组按钮移动，标签文字即时更新。保留卡片做位置过渡，新增卡片短淡入，移除卡片快速退场。容器更新采用最终真实排版，动画只负责旧位置与新位置之间的视觉衔接。

筛选导致列表变短时，不能让正在操作的按钮突然离开用户视野；动画期间可短暂锁定结果区高度，完成后释放。不要永久保留筛选前的大块空白。

### 5.2 手记搜索、排序与翻页

- 输入搜索：保持现有即时更新方式，不对每次按键重复播放滚动入场；旧动画可取消，焦点留在输入框。
- 排序：同一条手记从原位置移动到新位置，比整组消失再出现更容易理解。
- 类型和日期筛选：结果区局部淡入，选中态先响应，数量同步更新。
- 翻页：前后页可以采用相反的约 6–8px 小位移；只移动结果区，保持工具栏稳定，并延续现有分页焦点与滚动行为。
- 无结果：短淡入明确的无结果说明和清除筛选入口；不让容器反复塌陷或持续显示加载动画。

### 5.3 项目详情标签与截图

功能标签的选中背景连续移动。切换时，截图做局部叠化，文字做约 4–6px 的短位移；左右方向只在标签有明确顺序时使用。快速切换直接去最后一个标签。

新截图解码前保留现有图，准备成功再替换；失败则给出可重试的反馈。标签、说明和图片共同指向同一项，不能只更新其中一部分。

点击截图时，从该图片展开到查看器；关闭回到来源图并恢复焦点。遮罩、图片与关闭按钮分别处理透明度，图片本体不做高强度模糊。图片尺寸和滚动锁定在打开前确定，避免页面横向跳动。

### 5.4 日历、搜索层与手机菜单

日历切月：标题与日期网格一同短叠化，按前后月给予轻微方向提示；日历面板外框保持稳定。选日期时使用单个选中底色移动，不让整个月份重复入场。

搜索层和手机菜单：面板展开、遮罩淡入，关闭更快；快捷键打开搜索时输入框立即可输入。支持打开到一半就关闭，并正确恢复焦点。

## 6. 可以增添的氛围与彩蛋

| 效果 | 推荐表现 | 触发与范围 |
| --- | --- | --- |
| 场景切换 | 新景观准备好后缓慢叠化；选中缩略图即时反馈 | 用户主动选择，仅背景层 |
| 一阵微风 | 现有花瓣短暂偏向同一风向，随后自然恢复 | 少量主动交互；复用当前花瓣系统 |
| 日夜变化 | 天空和整体色调平缓过渡，控件图标同步切换 | 主动切换主题或时间场景 |
| 收藏反馈 | 图标短促轻弹一次，邻近出现少量微光 | 点击收藏后一次，不持续闪烁 |
| 专注完成 | 播放器附近散开少量花瓣，给出完成提示 | 完成后一次；音乐空间内 |
| 音乐沉浸 | 专辑图、歌词与背景光影随播放状态变化 | 用户进入音乐模式后启用 |

博客默认保持均衡强度；音乐空间可以更丰富。真实频谱需要另做音源与跨域兼容验证，当前 CSS 跳动条不能直接称为真实频谱，详见已有音乐方案。

不推荐全站鼠标拖尾、持续旋转卡片、滚动劫持、每段文字逐字出现或频繁的全屏遮罩。这些效果会占据阅读注意力，也不贴合当前稳定的风景与纸面视觉。

## 7. 实现边界与节奏

当前 Astro、CSS、Web Animations API 与已有 Motion 足以覆盖主要需求，无需为这些效果引入 React 或更换路由。Astro 的路由生命周期和元素衔接应遵循 [View Transitions 官方指南](https://docs.astro.build/en/guides/view-transitions/)。

- 短反馈约 100–160ms，控件展开约 180–240ms，内容变化约 220–300ms，背景叠化约 450–700ms。
- 入场快速开始、平缓落定；退出更短；位置变化保持连续；普通按钮不使用明显回弹。
- 逐帧动画优先改变 transform 与 opacity；位置测量集中进行，避免交替测量与写入。参见 [web.dev 动画性能指南](https://web.dev/articles/animations-guide)。
- 不以修改字号、容器宽度、桌面边距或首屏高度来制造动效；不对真实根容器施加缩放和平移。
- 不同时让全页转场、滚动入场、筛选位移控制同一个元素；路由切换时清理监听器、观察器和旧动画。
- 图片展开仅在资源和语义确实对应时启用；字体、截图比例差异明显时改用淡入，避免文字拉伸。
- 手机保留点击、选择、切换反馈，关闭依赖鼠标的光斑与跟随；减少动态模式直接更新或仅短淡入，关闭循环装饰和大位移。
- 动效关闭、页面不可见和图片加载失败都应有明确的静态状态，不能残留半透明卡片或遮挡点击的快照层。

## 8. 建议落地顺序与验收

第一批完成首页卡片生命周期、分类选中态、筛选与排序连续性、页面转场统一，以及详情标签的局部切换。它们覆盖使用频率最高的操作，先解决重复入场和快速切换时的冲突。

第二批选择两个有辨识度的效果：列表到详情的名称／同图衔接，以及截图原位展开。随后再完善背景切换和音乐模式的氛围联动。

第三批按实际体验决定是否增加微风、收藏微光和专注完成花瓣；每一处彩蛋都限制范围与触发频率。

实现后的验收包括：

1. 对照原页面检查电脑端容器居中、项目列数、侧栏、卡片尺寸和底部完整性；覆盖常用桌面宽度及手机单列。
2. 连续快速筛选、悬停、换页和返回，确认没有动画排队、双重位移、遗留遮罩或点不中的卡片。
3. 滚动离开再回来不重复入场；返回列表保留已存在的状态；输入搜索不被动画拖慢。
4. 键盘操作、焦点恢复、系统减少动态、动效关闭和浏览器功能回退均可正常使用。
5. 在实际浏览器记录性能，检查背景、图片解码与快照同时出现时是否有明显掉帧；验证后再报告流畅性，不预先承诺帧率。
