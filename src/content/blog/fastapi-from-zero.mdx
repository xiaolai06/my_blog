## 从一个真正能走通的目标开始

这份笔记围绕一个**本地、单用户的学习笔记 API**展开：创建笔记、按主题查询、分页、读取详情、修改完成状态与删除。它有数据库，能拒绝不合法输入，也有覆盖关键行为的测试。沿着这条小链路，可以看清框架各部分为什么存在。

## FastAPI 由什么组成：先画清职责边界

| 部件 | 它负责什么 | 在示例中怎样出现 |
| --- | --- | --- |
| HTTP | 方法、路径、头、状态码和请求 / 响应体 | `POST /notes`、JSON、201、401、422 |
| ASGI | Python 异步 Web 服务器与应用之间的接口约定 | Uvicorn 调用 FastAPI 应用 |
| Uvicorn | 监听端口、处理连接、运行 ASGI 应用 | 启动命令与 host / port |
| Starlette | 路由、中间件、请求响应等 Web 基础能力 | FastAPI 建立在其上，使用 CORS 中间件与测试客户端 |
| FastAPI | 通过函数签名组织路径操作、依赖、文档与模型 | `FastAPI`、`APIRouter`、`Depends` |
| Pydantic | 对输入输出建立模型，解析并验证字段 | `NoteCreate`、`NoteRead`、Settings |
| SQLModel / SQLAlchemy | 将 Python 对象、查询和事务连接到关系数据库 | `Session`、`select`、`commit` |
| SQLite | 真正持久保存数据的数据库 | 本地 `notes.db` 文件 |

FastAPI 不是数据库，也不会因为写了 `str` 就帮你建立权限系统。Python 的普通类型提示主要帮助工具和开发者；框架拿到请求时，才根据声明执行运行时解析与校验。Pydantic 默认还可能转换某些兼容类型，需要严格拒绝时应显式选择严格约束，并用测试确认。

这里采用 SQLModel，是为了用较小的代码连接模型与 SQLAlchemy。项目也可以直接使用 SQLAlchemy，或使用配套的异步驱动；这是数据访问方案，不是 FastAPI 必须绑定的唯一选择。框架起点与自动文档见[官方第一步](https://fastapi.tiangolo.com/tutorial/first-steps/)，数据库组合见[关系数据库教程](https://fastapi.tiangolo.com/tutorial/sql-databases/)。

## 先定义接口契约，再写实现

把行为列清楚，可以防止“有几个路由”被误当成“接口完成了”。本例所有 `/notes` 接口都需要 `X-API-Key`，而 `/health`、文档与 OpenAPI 是本地学习用的公开入口。

| 方法与路径 | 输入 | 正常结果 | 需要检验的失败 |
| --- | --- | --- | --- |
| `POST /notes` | title、可选 body / topic / done | 201 + 新笔记 | 空白标题、未知字段 → 422 |
| `GET /notes` | 可选 topic、offset、limit | 200 + 有序数组 | limit 超界或类型错误 → 422 |
| `GET /notes/{note_id}` | 正整数 ID | 200 + 笔记 | 不存在 → 404 |
| `PATCH /notes/{note_id}` | 至少一个待修改字段 | 200 + 修改后的笔记 | 空对象或显式 null → 422 |
| `DELETE /notes/{note_id}` | ID | 204，无响应体 | 不存在 → 404 |
| `GET /health` | 无 | 200 + status | 只证明服务能响应，不检查数据库 |

路径参数标识资源，查询参数表达筛选与分页，请求体承载创建或修改内容，请求头携带门禁凭据。`/notes?topic=web&limit=20` 不会创建笔记；`POST /notes` 也不应靠 URL 拼接一大段正文。

身份不成立与参数格式错误是不同问题。本文的错误顺序不作为承诺：依赖与字段校验可能共同参与请求解析，调用者不应靠“先收到 401 还是 422”推断系统内部结构。

四个模型解决不同问题：`Note` 是存储表；`NoteCreate` 限定允许写入的字段；`NotePatch` 表示局部修改；`NoteRead` 决定对外输出。即使字段暂时很相似，也不直接把数据库对象所有属性交给客户端。

`Title` 会去除首尾空白并检查长度，所以 `"   "` 不会作为有效标题写入。`extra="forbid"` 使偷偷添加的 `ownerId` 等字段失败；但这仍不是资源授权，授权必须依据真实用户在服务端判断。`response_model` 会参与输出校验、序列化与字段过滤，详见[响应模型文档](https://fastapi.tiangolo.com/tutorial/response-model/)。

PATCH 尤其容易写错：

| 请求内容 | 本例的含义 | 实现关键 |
| --- | --- | --- |
| 没有提供 `done` | 保持旧值 | `exclude_unset=True` |
| `{"done": false}` | 明确改为未完成 | 不能用 `if value` 跳过 false |
| `{"done": null}` | 本例不允许清空布尔字段 | 显式 null 校验 |
| `{}` | 没有任何修改意图 | 路由拒绝空修改 |

`Optional` / `T | None` 只表达可空类型，不自动决定“没传时怎样处理”。本例字段默认 None 用来支持省略，但字段真的被提交为 null 时会拒绝；如果业务允许清空描述，应单独设计这个契约，不能全字段照搬。

`Depends` 让框架在调用路径函数之前解析可复用的依赖。`Security(APIKeyHeader)` 从请求头取凭据，并使 OpenAPI 能声明安全方案；`compare_digest` 比较字节值，避免自行写逐字符比较。这个共享 Key 只区分“知道 Key”与“不知道 Key”，没有用户身份、角色或撤销某个用户会话的能力。

真正的多用户服务还需登录、密码哈希或身份提供商、会话 / Token 校验，以及查询中的 owner 范围。不要把这个公开教学 Key 放进浏览器构建产物后，再宣称 API 被保密。

## def 与 async def：按调用的库选择，而不是按名字选择

本例使用同步 SQLModel Session，因此路径函数使用普通 `def`，框架会在线程池运行这类路径函数和同步依赖。它减少阻塞事件循环的风险，但线程池仍是有限资源。普通工具函数不会因为被 async 路由调用，就自动搬到线程池。

| 场景 | 合适的起点 | 容易造成的问题 |
| --- | --- | --- |
| 同步数据库、同步第三方库 | `def` 路由，或明确的线程卸载 | 在 async 函数中直接执行长时间同步 I/O |
| 异步数据库驱动、异步 HTTP 客户端 | `async def` 配合 await | 使用 async 外壳却调用阻塞库 |
| CPU 密集图像处理、大量计算 | 进程、任务队列或独立服务 | 以为 await 能让 CPU 运算自动并行 |
| 需要可靠重试的长任务 | 持久任务队列与任务状态 | 把响应后的进程内任务当成可靠消息系统 |

并发是多项工作交替推进，并行是同时计算；`async` 主要让等待 I/O 时可以处理别的请求，不会让一条 SQL 自动更快。BackgroundTasks 适合短小的响应后工作，进程退出会影响它；它不保证持久化、重试或跨机器调度。概念与框架线程池行为见[官方并发说明](https://fastapi.tiangolo.com/async/)。

## 从教学接口到线上服务，还缺哪些环节

| 需要补齐的环节 | 为什么示例还不够 | 可执行的下一步 |
| --- | --- | --- |
| 用户与资源授权 | 一个共享 Key 没有 owner 隔离 | 为真实身份建立服务端查询范围，测试跨用户访问 |
| 数据迁移 | create_all 不升级旧表 | 建立版本迁移，在测试副本演练后部署 |
| 错误与日志 | 500 不能只留一段终端输出 | 请求标识、结构化日志、脱敏和通知 |
| 运行与容量 | reload 进程不是运维方案 | 进程管理、超时、负载测试与资源上限 |
| 备份与恢复 | 单个 SQLite 文件也可能损坏或误删 | 了解 WAL 与一致性备份，演练恢复 |
| HTTPS 与入口 | API 逻辑正常不等于公网可用 | 反向代理、域名、证书和续期验收 |

多个 worker 不能共享进程内 Map；同步 Session 也不应跨请求共享。选 SQLite 还是服务端数据库取决于写并发、运维与备份需求，不依据“FastAPI 很快”一句话决定。密钥、连接串不能放到浏览器可见变量中。

关于域名和证书，可接着读 [DNS 与 HTTPS 实践](/blog/duckdns-domain-https/)；[服务器部署笔记](/blog/astro-server-deployment/)以静态 Astro 站点为对象，可以复用入口检查思路，但 Python 服务还需要进程和代理配置，不能直接照搬静态文件配置。

## 遇到错误时，先看它属于哪一层

| 现象 | 优先检查 | 不应急着做什么 |
| --- | --- | --- |
| `ModuleNotFoundError` | 解释器、虚拟环境、工作目录 | 反复往不同 Python 安装同一依赖 |
| 启动要求 NOTES_API_KEY | 是否复制模板、变量前缀和长度 | 给代码加一个公开默认生产 Key |
| `no such table` | 是否启动 lifespan、是否启动了另一份 DB | 删除数据库“重来” |
| 401 | 是否向正确端口发送 X-API-Key | 通过放宽 CORS 解决身份验证 |
| 422 | 错误路径、字段类型、空白 / null 约定 | 直接关闭输入校验 |
| 404 | 路径还是资源不存在，ID 是否正确 | 把未知记录统一返回空的成功对象 |
| 浏览器失败而 curl 正常 | origin、预检方法 / 头与代理 | 将所有来源无条件放行 |
| 更新后其他字段被清空 | 是否把未提交字段也写入 | 用默认值覆盖整个对象 |

可以做三个练习检查自己是否理解：给列表增加 done 筛选；允许 body 显式 null 表示清空但标题仍拒绝；增加一个必须两次写入同时成功的操作。每个练习先写输入与失败约定，再补测试，最后改实现。

## 参考资料的阅读顺序

先读 [First Steps](https://fastapi.tiangolo.com/tutorial/first-steps/)理解应用与 OpenAPI，再读 [APIRouter](https://fastapi.tiangolo.com/tutorial/bigger-applications/)和[依赖](https://fastapi.tiangolo.com/tutorial/dependencies/)理解组织方式，随后查[模型](https://fastapi.tiangolo.com/tutorial/response-model/)、[数据库](https://fastapi.tiangolo.com/tutorial/sql-databases/)和[并发](https://fastapi.tiangolo.com/async/)。需要更大应用的架构参考时，再看官方的 [full-stack-fastapi-template](https://github.com/fastapi/full-stack-fastapi-template)。模板的数据库、部署和功能范围与本文不同，不要只挑一个文件拼进当前例子就期待整套行为自动成立。

框架知识最终应能回答这几个问题：请求从哪里进入，输入在哪里受约束，依赖什么时候创建，事务何时提交，响应暴露哪些字段，失败之后怎样确认没有留下错误数据。能沿源码和测试回答出来，才有继续扩展的基础。
